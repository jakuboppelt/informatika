Příkazová řádka a git

Jak ovládat počítač příkazy místo myši a jak si v projektu uchovávat verze pomocí gitu. Obojí si vyzkoušíš na svém počítači v osmi cvičeních.

Po přečtení bys měl umět

  • vysvětlit rozdíl mezi terminálem a shellem
  • otevřít příkazovou řádku ve svém systému
  • rozlišit absolutní a relativní cestu
  • pohybovat se po složkách a vytvářet, kopírovat, přesouvat a mazat soubory
  • vysvětlit, co je git a čím se liší od GitHubu
  • založit repozitář a uložit první verzi projektu
  • používat git status, add, commit, log a diff
  • vyřadit soubor z gitu pomocí .gitignore

Příkazová řádka

Terminál a shell

Příkazová řádka (anglicky command line interface, CLI) je způsob ovládání počítače textem: napíšeš příkaz, stiskneš Enter a počítač vypíše výsledek. Je to opak grafického rozhraní (GUI), kde klikáš myší.

Často se zaměňují dva pojmy:

  • Terminál je okno, do kterého píšeš a ve kterém se zobrazuje text. Například Windows Terminal nebo Terminál v macOS.
  • Shell je program, který tvoje příkazy čte a provádí. Ve Windows je to PowerShell (a starší cmd), v macOS zsh, v Linuxu nejčastěji bash.

Proč se to učit, když existuje myš?

  • Rychlost. Přejmenovat 300 souborů myší trvá půl hodiny, příkazem sekundu.
  • Opakovatelnost. Příkaz si uložíš, pošleš spolužákovi nebo spustíš znovu. Postup klikání se předává špatně.
  • Nástroje programátora. Git, Python, správci balíčků a překladače se ovládají hlavně z příkazové řádky.
  • Servery. Na většině serverů žádná grafika není. Připojíš se přes síť a máš jen terminál.

Bash i ve Windows

S instalací gitu pro Windows dostaneš i Git Bash, tedy bash, jaký je na Linuxu a macOS. Příkazy z tohoto textu v něm fungují beze změny. Většina z nich ale funguje i v PowerShellu, rozdíly jsou v tabulkách.

Jak vypadá příkaz

Před kurzorem je prompt (výzva). Ukazuje, kdo jsi a ve které složce se nacházíš. Za ním píšeš příkaz:

promptstudent@pc:~$ příkazls přepínač-l argumentdokumenty
  • Příkaz je název programu, který se spustí: ls vypíše obsah složky.
  • Přepínač (option, flag) mění chování. Začíná pomlčkou: -l znamená podrobný výpis. Dlouhé přepínače mají dvě pomlčky: --help.
  • Argument říká, s čím má příkaz pracovat: se složkou dokumenty.

Části se oddělují mezerou. Proto když název obsahuje mezeru, musíš ho dát do uvozovek: cd "Moje dokumenty". Jinak shell pochopí Moje a dokumenty jako dva argumenty. Velikost písmen v Linuxu a macOS záleží: Skola.txt a skola.txt jsou dva různé soubory.

Proč názvy bez mezer a diakritiky

Soubor ukol_1.txt napíšeš v terminálu rychle a bez chyby. Úkol č. 1.txt potřebuje uvozovky a české znaky, které se v některých nástrojích rozbijí. Pojmenovávej soubory malými písmeny, bez mezer a bez diakritiky.

Cesty ke složkám

Soubory jsou uložené ve stromu složek. Cesta popisuje, jak se k souboru dostat.

  • Absolutní cesta začíná od kořene. V Linuxu a macOS od /, například /home/student/dokumenty/skola.txt. Ve Windows od písmene disku: C:\Users\student\Documents\skola.txt. Platí odkudkoli.
  • Relativní cesta začíná ve složce, kde právě jsi. Když jsi v /home/student, stačí napsat dokumenty/skola.txt.
ZápisVýznam

Čtení, zápis a hledání

Terminál
cat skola.txt                  # vypíše obsah souboru
echo "Ahoj"                    # vypíše text
echo "Můj projekt" > README.md   # zapíše text do souboru (přepíše ho)
echo "Druhý řádek" >> README.md  # připíše text na konec souboru

V PowerShellu se místo grep používá sls (Select-String): sls TODO skola.txt, ve všech souborech ls -r | sls TODO.

Když nevíš, jak příkaz použít:

  • ls --help vypíše krátkou nápovědu.

  • Web tldr.sh ukazuje u každého příkazu nejčastější příklady použití.

Na co si dát pozor

rm nemá koš

Soubor smazaný příkazem rm nejde do koše a terminál se nezeptá „Opravdu?“. Před rm -r si vždy zkontroluj, kde jsi (pwd) a co mažeš (ls).

  • Nespouštěj příkazy, kterým nerozumíš. Hlavně ne ty, které ti někdo pošle se slovy „tohle ti to opraví“. Příkaz z internetu může smazat data nebo stáhnout škodlivý program.
  • Pozor na sudo (Linux, macOS) a na terminál spuštěný jako správce (Windows). Příkaz pak smí měnit celý systém, ne jen tvoje soubory.
  • Chybová hláška je nápověda. No such file or directory znamená, že soubor na té cestě není. Zkontroluj překlep a složku, ve které jsi.

Cvičení: příkazová řádka

Cvičení 1

Orientace

5 min

Otevři terminál na svém počítači a projdi kroky. Po každém příkazu si přečti, co terminál vypsal.

  1. pwd: ve které složce terminál začíná?
  2. ls: co v ní je?
  3. cd Documents: přejdi do dokumentů. Zkus napsat jen cd Doc a stisknout Tab.
  4. pwd a ls: kde jsi teď a co tu máš?
  5. cd .. a pwd: jsi zpátky v domovské složce?
Co bys měl vidět po prvním pwd
C:\Users\jmeno        # Windows (PowerShell ho vypíše pod nadpisem Path)
/Users/jmeno          # macOS
/home/jmeno           # Linux
Otázka k zamyšlení

Proč v terminálu vidíš Documents a Downloads, když Průzkumník ukazuje Dokumenty a Stažené soubory?

Odpověď

Skutečné názvy složek jsou anglické. Průzkumník (i Finder v macOS) jen zobrazuje přeložený název. Terminál ukazuje, jak se složka doopravdy jmenuje.

Cvičení 2

Vlastní pracovní složka

10 min

Založ si složku cviceni, ve které budeš zkoušet všechno ostatní. Nic mimo ni neměň.

Terminál
cd ~
mkdir cviceni
cd cviceni
mkdir projekt
mkdir fotky
echo "Pondělí: seminář" > plan.txt
echo "Úterý: trénink" >> plan.txt
cat plan.txt

Pak vytvoř prázdný soubor poznamky.txt: v bashi touch poznamky.txt, v PowerShellu ni poznamky.txt. A pokračuj:

  1. Zkopíruj plan.txt do složky projekt.
  2. Přesuň poznamky.txt do složky projekt.
  3. Přejmenuj plan.txt na plan_tydne.txt.
  4. Vypiš obsah složky cviceni i složky projekt.
  5. Otevři složku v grafickém prohlížeči: explorer . (Windows) nebo open . (macOS). Tečka znamená aktuální složku.
Nápověda

Kopírování je cp, přesun i přejmenování mv. První argument je odkud, druhý kam.

Řešení
cp plan.txt projekt/
mv poznamky.txt projekt/
mv plan.txt plan_tydne.txt
ls
ls projekt

Ve složce cviceni mají zůstat fotky, plan_tydne.txt a projekt. Ve složce projekt jsou plan.txt a poznamky.txt.

Cvičení 3

Hledání v souborech

5 min

Ve složce cviceni vytvoř tři soubory a pak najdi ty, ve kterých je slovo TODO.

Terminál
echo "TODO: dopsat úvod" > referat.txt
echo "Hotovo" > ukol.txt
echo "TODO: najít zdroje" > projekt/zdroje.txt
Nápověda

V bashi grep s přepínačem -r, v PowerShellu ls -r a výsledek poslat do sls.

Řešení
grep -r TODO .           # bash, macOS
ls -r | sls TODO         # PowerShell

Výsledkem jsou dva soubory, referat.txt a projekt/zdroje.txt. Soubor ukol.txt ve výpisu není.

Úklid

5 min

Smaž soubor ukol.txt a složku fotky. Před mazáním si příkazem pwd ověř, že jsi ve složce cviceni.

Řešení
pwd
rm ukol.txt
rm -r fotky

Podívej se do koše. Smazané soubory v něm nejsou.

Git

Co je git

Git je systém pro správu verzí (version control system, VCS). Hlídá složku s projektem a na tvůj pokyn uloží její stav jako novou verzi. Ke každé verzi se dá kdykoli vrátit a porovnat ji s jinou.

Bez gitu vypadá správa verzí takhle: projekt, projekt_kopie, projekt_final, projekt_final2_opraveny. Nikdo neví, co se v které kopii změnilo a která je poslední. S gitem máš jednu složku a v ní celou historii: kdo, kdy, co a proč změnil.

Git vytvořil v roce 2005 Linus Torvalds, autor Linuxu, pro vývoj linuxového jádra. Dnes ho používá prakticky každý softwarový projekt.

Git není GitHub

Git je program na tvém počítači a funguje i bez internetu. GitHub je webová služba, kam můžeš repozitář nahrát: slouží jako záloha, ke sdílení a ke spolupráci. Podobných služeb je víc, například GitLab nebo Bitbucket.

Základní pojmy

  • Repozitář (repo) je složka projektu, kterou git sleduje. Historii si ukládá do skryté podsložky .git.
  • Commit je uložená verze: snímek projektu se zprávou, autorem a časem. Každý má jednoznačný identifikátor (hash), například a3f9c21.
  • Pracovní složka jsou běžné soubory, které upravuješ v editoru.
  • Staging (index, přípravná oblast) je seznam změn, které půjdou do příštího commitu. Díky němu si vybereš, co uložit, a ne vždy všechno najednou.
  • Větev (branch) je samostatná linie historie. Hlavní větev se jmenuje main (ve starších nastaveních master). Pro začátek ti jedna větev stačí.

Změna souboru prochází třemi místy na tvém počítači. Volitelně pak čtvrtým na serveru:

Pracovní složkasoubory upravuješ v editoru
Stagingvybrané změny připravené k uložení
Repozitářuložené verze ve složce .git
GitHubkopie na serveru, záloha a sdílení
git add →git commit →git push →

Instalace a první nastavení

Ve Windows stáhni git z git-scm.com, nebo ho nainstaluj příkazem winget install Git.Git. V macOS se nabídne instalace sama, když poprvé napíšeš git. V Linuxu například sudo apt install git. Pak terminál zavři a otevři znovu.

Ověř instalaci a nastav jméno a e-mail. Git je zapisuje do každého commitu jako autora. Nastavuje se to jednou na každém počítači:

Terminál
git --version
git config --global user.name "Jan Novák"
git config --global user.email "jan.novak@example.com"
git config --global init.defaultBranch main

Poslední řádek zajistí, že se hlavní větev v nových repozitářích bude jmenovat main. Pokud budeš používat GitHub, zadej stejný e-mail jako u účtu na GitHubu.

Založení repozitáře

Přejdi do složky projektu a napiš git init:

Terminál
cd ~/projekty/web
git init

Git odpoví Initialized empty Git repository in …/web/.git/. Vznikla skrytá složka .git, ve které bude celá historie. Tvoje soubory se nezměnily a zatím není uložená žádná verze.

Druhá možnost je stáhnout existující repozitář, třeba z GitHubu. Příkaz git clone vytvoří složku i s celou historií:

Terminál
git clone https://github.com/jakuboppelt/informatika.git
Složku .git nemaž

Když smažeš .git, smažeš celou historii. Soubory projektu zůstanou, ale všechny uložené verze zmizí. Repozitář také nezakládej v domovské složce nebo na celém disku, ale vždy ve složce jednoho projektu.

Základní cyklus: status, add, commit

Práce s gitem je pořád dokola stejná:

  1. Uprav soubory v editoru jako obvykle.
  2. git status: podívej se, co se změnilo.
  3. git add: připrav změny do stagingu.
  4. git commit -m "zpráva": ulož je jako novou verzi.
Terminál
git status                 # co se změnilo a co je připravené
git add index.html         # připraví jeden soubor
git add .                  # připraví všechny změny ve složce
git commit -m "Přidán formulář pro přihlášení"

git status spouštěj často, nic nezmění a vždy ti řekne, v jakém stavu jsi. Soubory ve výpisu dělí na tři skupiny:

Ve výpisuZnamenáCo s tím
Untracked filesnový soubor, git ho zatím nesledujegit add, nebo zapsat do .gitignore
Changes not staged for commitsledovaný soubor se změnil, ale změna není připravenágit add
Changes to be committedpřipraveno ve stagingugit commit

Jak psát zprávu commitu

Zpráva má říct, co commit dělá a případně proč. Dobrá pomůcka: doplň větu „Tento commit…“. Píše se krátce, do první řádky asi 50 znaků.

Špatně

oprava, asdf, změny, final

Dobře

Oprava pádu při prázdném seznamu
Přidána stránka s kontaktem

Commituj často a po malých krocích: jeden commit, jedna logická změna. Ne jeden obří commit večer před odevzdáním.

Historie a změny

Terminál
git log                # historie commitů s autorem a datem
git log --oneline      # zkrácená historie, jeden commit na řádek
git diff               # co přesně se změnilo a ještě není připravené
git diff --staged      # co je připravené k commitu
git restore index.html # zahodí neuložené změny souboru

Výstup git diff označuje přidané řádky znaménkem + a odebrané znaménkem -. Pokud je výpis delší než okno, listuješ mezerníkem a ukončíš ho klávesou Q.

git restore je nevratný

git restore soubor vrátí soubor do stavu posledního commitu (přesněji do stavu ve stagingu). Úpravy, které jsi neuložil commitem, jsou pryč.

Soubor .gitignore

Některé soubory do repozitáře nepatří: hesla a klíče, soubory s nastavením tvého počítače, stažené knihovny nebo soubory, které vznikají při spuštění programu. Jejich názvy napiš do souboru .gitignore v hlavní složce projektu, každý na jeden řádek:

.gitignore
# tajné údaje
heslo.txt
.env

# stažené knihovny a dočasné soubory
node_modules/
__pycache__/
*.log

Lomítko na konci znamená celou složku, hvězdička libovolný text: *.log jsou všechny soubory s příponou .log. Soubor .gitignore samotný do gitu commitni, ať platí pro všechny, kdo s projektem pracují.

Když už jsi soubor omylem přidal přes git add, ale ještě necommitnul, vyřadíš ho ze stagingu příkazem git rm --cached heslo.txt. Soubor na disku zůstane.

.gitignore vytvoř hned na začátku

Ignoruje jen soubory, které git ještě nesleduje. Když heslo jednou commitneš, zůstane v historii, i když ho pak smažeš. Takové heslo je potřeba změnit.

Tip pro Windows

Soubor .gitignore vytvářej v editoru (třeba VS Code), ne příkazem echo … > .gitignore ve Windows PowerShellu. Starší PowerShell zapisuje přesměrovaný text v kódování UTF-16, kterému git v .gitignore nerozumí.

Cvičení: git

Cvičení 5

Nastavení gitu

5 min

Ověř, že máš git nainstalovaný, a nastav jméno a e-mail. Použij svoje skutečné jméno.

Terminál
git --version
git config --global user.name "Jan Novák"
git config --global user.email "jan.novak@example.com"
git config --global init.defaultBranch main
git config --global --list

Poslední příkaz vypíše nastavení. Mezi řádky musíš najít user.name=… a user.email=… se svými údaji.

Terminál hlásí, že příkaz git nezná

Git není nainstalovaný, nebo terminál běžel už před instalací. Nainstaluj git (winget install Git.Git), terminál zavři a otevři znovu.

Cvičení 6

První repozitář

15 min

Založ repozitář pro malý web a ulož jeho první verzi. Soubor s heslem do gitu nepustíš.

Terminál
cd ~/cviceni
mkdir web
cd web
git init
  1. Vytvoř index.html v editoru: code index.html (VS Code) nebo notepad index.html. Napiš do něj <h1>Můj web</h1> a ulož.
  2. Vytvoř heslo.txt se slovem admin123, třeba echo admin123 > heslo.txt.
  3. git status: oba soubory jsou v sekci Untracked files.
  4. Vytvoř .gitignore v editoru (code .gitignore nebo notepad .gitignore) s jediným řádkem heslo.txt a ulož.
  5. git status: heslo.txt zmizel, místo něj je tu .gitignore.
  6. git add . a znovu git status: soubory jsou v Changes to be committed.
  7. git commit -m "První verze webu"
  8. git log: vidíš svůj commit se jménem a datem.
Co bys měl vidět po commitu
[main (root-commit) 3f2a9c1] První verze webu
 2 files changed, 2 insertions(+)
 create mode 100644 .gitignore
 create mode 100644 index.html

Kód 3f2a9c1 budeš mít jiný, každý commit má vlastní.

Proč soubory v editoru, a ne přes echo

Starší Windows PowerShell ukládá text zapsaný přes > v kódování UTF-16. Git takový soubor považuje za binární a neukáže v něm změny. U heslo.txt to nevadí, ten do gitu nejde.

Git píše „LF will be replaced by CRLF“

To je jen upozornění, ne chyba. Windows a Linux ukončují řádky jinými znaky a git je při ukládání sjednocuje.

V git status je pořád heslo.txt

Zkontroluj, že se soubor jmenuje přesně .gitignore (s tečkou na začátku, bez přípony .txt) a leží ve složce web. Vypiš ho: cat .gitignore. Pokud jsi heslo už přidal přes git add, vyřaď ho příkazem git rm --cached heslo.txt.

Cvičení 7

Druhá verze

10 min
  1. Do index.html připiš řádek <p>Ahoj, tohle je můj web.</p> a ulož.
  2. git status: soubor je modified.
  3. git diff: nový řádek je označený +. Z výpisu odejdeš klávesou Q.
  4. Ulož změnu jako nový commit s výstižnou zprávou.
  5. git log --oneline: v historii jsou dva commity.
Řešení
git add index.html
git commit -m "Přidán úvodní odstavec"
git log --oneline
Cvičení 8

Záchrana

5 min

Teď uvidíš, k čemu je git dobrý.

  1. V editoru z index.html smaž úplně všechno a ulož.
  2. git status a git diff: git ví, že řádky zmizely.
  3. git restore index.html
  4. Podívej se do editoru. Soubor je zpátky ve stavu posledního commitu.
Otázka k zamyšlení

Co kdybys smazaný soubor nejdřív commitnul? Je tvoje práce ztracená?

Odpověď

Není. Starší verze zůstala v historii. Příkaz git restore --source=HEAD~1 index.html vrátí soubor ve stavu o jeden commit zpět. Proto se vyplatí commitovat často.

Kam dál

Jak repozitář nahrát na GitHub (git remote, git push, git pull) a jak pracovat s větvemi, probereme samostatně. Na práci na vlastním projektu ti zatím stačí to, co je v tomto textu.

Otázky k opakování

Jaký je rozdíl mezi terminálem a shellem?

Terminál je okno, které zobrazuje text a přijímá vstup z klávesnice. Shell je program, který příkazy zpracovává a spouští (bash, zsh, PowerShell).

Z jakých částí se skládá příkaz ls -l dokumenty?

Z příkazu ls, přepínače -l (podrobný výpis) a argumentu dokumenty (se kterou složkou pracovat).

Jaký je rozdíl mezi absolutní a relativní cestou?

Absolutní cesta začíná od kořene (/ nebo C:\) a platí odkudkoli. Relativní začíná v aktuální složce, takže záleží na tom, kde právě jsi.

Co znamenají ~, . a ..?

Domovskou složku, aktuální složku a nadřazenou složku.

Jak přejmenuješ soubor?

Příkazem mv stary_nazev nový_nazev. Přejmenování je přesun na jiný název.

Jaký je rozdíl mezi > a >>?

> zapíše výstup do souboru a jeho původní obsah přepíše. >> výstup připíše na konec souboru.

Proč je rm nebezpečnější než mazání v Průzkumníku?

Nepoužívá koš a neptá se na potvrzení. Smazaný soubor se běžně nedá obnovit.

Co je git a čím se liší od GitHubu?

Git je program pro správu verzí, který běží na tvém počítači i bez internetu. GitHub je webová služba, kam se repozitáře nahrávají kvůli záloze, sdílení a spolupráci.

Co se stane po git init?

V aktuální složce vznikne skrytá složka .git, do které git ukládá historii. Soubory projektu se nezmění a zatím není uložená žádná verze.

K čemu je staging a proč se nedělá commit rovnou?

Staging je přípravná oblast. Pomocí git add vybereš, které změny patří do příštího commitu. Můžeš tak rozdělit práci na několik logických commitů.

Proč git po prvním commitu hlásí „Author identity unknown“?

Není nastavené jméno a e-mail autora. Nastaví se příkazy git config --global user.name a git config --global user.email.

Co patří do .gitignore a proč ho vytvořit hned na začátku?

Hesla, klíče, stažené knihovny, dočasné a vygenerované soubory. Soubor, který už byl jednou commitnutý, zůstane v historii, i když ho později přidáš do .gitignore.
