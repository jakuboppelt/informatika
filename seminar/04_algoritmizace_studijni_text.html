Algoritmus a algoritmizace

Algoritmus je přesný a konečný postup, který pro každý přípustný vstup vede k řešení dané úlohy. Slovo pochází ze jména perského matematika al-Chwárizmího (9. století).

Algoritmizace je proces, při kterém problém převádíme na algoritmus: problém analyzujeme, určíme vstupy a výstupy, rozložíme ho na menší části a navrhneme postup. Program je zápis algoritmu v konkrétním programovacím jazyce.

Algoritmus nemusí vykonávat počítač. Algoritmem je i písemné sčítání pod sebou nebo kuchařský recept, pokud je dostatečně přesný.

Řídicí struktury

Každý algoritmus lze složit ze tří základních struktur (věta o strukturovaném programování):

  • Posloupnost (sekvence): příkazy se provedou jeden po druhém.
  • Větvení (selekce): podle podmínky se provede jedna z větví. Úplné větvení má obě větve, neúplné jen jednu.
  • Cyklus (iterace): část se opakuje. Rozlišujeme cyklus s daným počtem opakování, s podmínkou na začátku (nemusí proběhnout ani jednou) a s podmínkou na konci (proběhne alespoň jednou).

Dalšími pojmy jsou proměnná (pojmenované místo pro hodnotu), podprogram (funkce) a rekurze (algoritmus volá sám sebe na menším vstupu).

Praktický příklad: Eukleidův algoritmus

Úloha: najít největší společný dělitel (NSD) dvou přirozených čísel.

Slovně: Dokud druhé číslo není nula, nahraď dvojici (a, b) dvojicí (b, zbytek po dělení a číslem b). Výsledkem je první číslo.

Pseudokód a Python:

def nsd(a, b):
    while b != 0:
        a, b = b, a % b
    return a

Ve vývojovém diagramu: začátek (ovál) → vstup a, b (rovnoběžník) → podmínka b ≠ 0? (kosočtverec). Větev ano: zbytek = a mod b, a = b, b = zbytek (obdélníky) a návrat k podmínce. Větev ne: výstup a (rovnoběžník) → konec (ovál).

Ověření vlastností: hodnota b se v každém kroku zmenší a nemůže klesnout pod nulu, takže algoritmus je konečný. Každý krok je jednoznačný a postup funguje pro libovolnou dvojici přirozených čísel.

Složitost algoritmu

Časová složitost udává, jak počet kroků roste s velikostí vstupu n. Paměťová složitost totéž říká o spotřebě paměti. Zapisuje se notací velké O.

ZápisNázevPříklad
O(1)konstantnípřístup k prvku pole podle indexu
O(log n)logaritmickábinární vyhledávání
O(n)lineárníhledání maxima
O(n log n)linearitmickářazení slučováním (merge sort)
O(n²)kvadratickábublinkové řazení
O(2ⁿ)exponenciálnízkoušení všech podmnožin

Využití

Algoritmy jsou základem veškerého softwaru: vyhledávání a řazení dat, hledání nejkratší cesty v navigaci, šifrování, komprese dat, doporučování obsahu, strojové učení. Algoritmické myšlení (rozklad problému, hledání vzorů, abstrakce) se uplatní i mimo informatiku.

Problém zastavení (halting problem)

Znění: Existuje algoritmus, který pro libovolný program a jeho vstup rozhodne, zda se program po konečném počtu kroků zastaví, nebo poběží donekonečna?

Odpověď: Neexistuje. Dokázal to Alan Turing v roce 1936. Problém zastavení je algoritmicky nerozhodnutelný.

Myšlenka důkazu (sporem):

  1. Předpokládejme, že existuje program H(program, vstup), který vždy správně odpoví „skončí“ nebo „neskončí“.
  2. Sestrojíme program D(program): zeptá se H, zda program spuštěný sám na sobě skončí. Pokud ano, D se zacyklí. Pokud ne, D skončí.
  3. Spustíme D(D). Odpoví-li H, že D(D) skončí, pak se D zacyklí. Odpoví-li, že neskončí, pak D skončí. V obou případech se H mýlí.
  4. To je spor s předpokladem, takže H nemůže existovat.
def D(program):
    if H(program, program) == "skončí":
        while True:      # zacykli se
            pass
    else:
        return           # skonči

Důsledky:

  • Existují přesně zadané úlohy, které nevyřeší žádný algoritmus, bez ohledu na výkon počítače.
  • Žádný nástroj neumí u každého programu spolehlivě odhalit nekonečný cyklus ani obecně ověřit, že program dělá, co má.
  • U konkrétního programu se zastavení často dokázat dá (viz Eukleidův algoritmus). Nejde to jedním univerzálním postupem pro všechny programy.

Nerozhodnutelnost není totéž co vysoká složitost: složitý problém je řešitelný, jen pomalu. Nerozhodnutelný problém obecně řešit nelze vůbec.
