Hash funkce

Otisk dat, ze kterého se data nedají vrátit. Jak hash funkce funguje, proč se kolize nedají úplně vyloučit, k čemu se používá a jak na ní stojí elektronický podpis.

Úplný začátek

Hash funkce je černá krabička

Něco do ní vložíš a vyjde z ní číslo. Pro stejný vstup vyjde vždy stejné číslo. Co se uvnitř krabičky děje, zatím nevíme. Tak se do ní podíváme.

Ze samotného výstupu nepoznáš, co bylo na vstupu. Zkus uhodnout, jaké pravidlo tahle krabička používá.

Otevřeme krabičku

Naše první hash funkce

Každé písmeno nahraď jeho pořadím v abecedě (A = 1, B = 2, … Z = 26). Čísla sečti a vezmi zbytek po dělení deseti. Ten zbytek je hash. Napiš vlastní slovo.

Co hračka umí a neumí

Stejný hash mají i různá slova

Spočítali jsme hash dvanácti slov. Červeně jsou ta, která mají hash shodný s nějakým jiným slovem.

Hashe jsou jen čísla od 0 do 9, takže se slova potkávají hned. Slova KOS, SOK a OKS mají vždy stejný hash, protože součet nezávisí na pořadí písmen. Z čísla 5 nepoznáš, které slovo to bylo.

Kolize

Kolizím se nedá vyhnout, jen je nenajít

Vstupů je nekonečně mnoho, hashů jen konečně mnoho, takže se některé vstupy musí potkat. Dobrá funkce zajistí, že je nikdo nedokáže najít. Vyber délku hashe.

HMAC

Hash s tajným klíčem

Obyčejný hash může spočítat každý. HMAC přidá tajný klíč: správný otisk spočítá jen ten, kdo klíč zná. Používá se u API, webhooků a v authenticatoru z minulé hodiny.

Zkus doma

Hash textu, souboru a HMAC

Spusť v Pythonu na svém počítači. Stačí standardní knihovna.

import hashlib, hmac, sys

# 1) Hash textu: jedno písmeno jinak a hash je úplně jiný
print(hashlib.sha256("Ahoj".encode()).hexdigest())
print(hashlib.sha256("ahoj".encode()).hexdigest())

# 2) Hash souboru po částech (funguje i pro velké soubory)
def hash_souboru(cesta, algoritmus="sha256"):
    h = hashlib.new(algoritmus)
    with open(cesta, "rb") as f:
        while blok := f.read(1024 * 1024):
            h.update(blok)
    return h.hexdigest()

print(hash_souboru(sys.argv[0]))   # hash tohoto skriptu

# 3) HMAC: hash s tajným klíčem
znacka = hmac.new(b"tajny-klic", b"prevod 100 Kc", hashlib.sha256).hexdigest()
print(znacka)

Zkus doplnit hash souboru, který jsi stáhl, a porovnat ho s hodnotou na webu. Zkus v souboru změnit jediný znak.

Zkus doma

Najdi kolizi zkráceného hashe

Z hashe vezmeme jen prvních 8 znaků (32 bitů) a hledáme dvě různé zprávy, které je mají stejné. Kolik pokusů to bude?

import hashlib, itertools, time

videno = {}
start = time.time()
for i in itertools.count():
    text = f"zprava {i}"
    kratky = hashlib.sha256(text.encode()).hexdigest()[:8]
    if kratky in videno:
        print("Kolize po", i + 1, "pokusech za", round(time.time() - start, 2), "s")
        print(videno[kratky], "a", text, "mají stejný začátek hashe", kratky)
        break
    videno[kratky] = text

Co uvidíš

Kolize se najde zhruba po 60 až 100 tisících pokusech, ne po čtyřech miliardách. To je narozeninový paradox: kolize vznikne po zhruba druhé odmocnině počtu možností. Zkus 10 hexadecimálních znaků (40 bitů). U plných 256 bitů by to bylo 2128 pokusů.

Zkus doma

Podepiš a ověř podpis

Elektronický podpis na několika řádcích. Potřebuješ balíček cryptography: pip install cryptography.

from cryptography.exceptions import InvalidSignature
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey

soukromy = Ed25519PrivateKey.generate()   # tajný klíč podepisujícího
verejny = soukromy.public_key()           # veřejný klíč, ten se rozdává

dokument = "Smlouva: 100 000 Kč".encode()
podpis = soukromy.sign(dokument)

for text in (dokument, "Smlouva: 900 000 Kč".encode()):
    try:
        verejny.verify(podpis, text)
        print(text.decode(), "-> podpis platí")
    except InvalidSignature:
        print(text.decode(), "-> PODPIS NEPLATÍ")

Ed25519 hashuje data uvnitř podpisového algoritmu. U RSA nebo ECDSA se hash počítá zvlášť a podepisuje se on.

Shrnutí

Co si odneseš

  • Hash funkce z dat libovolné délky vyrobí otisk pevné délky. Stejný vstup dá stejný hash, malá změna hash úplně změní a zpět se z něj data nespočítají.
  • Kolize existují vždy, jde o to, aby je nikdo nedokázal najít. Proto jsou MD5 a SHA-1 rozbité a používá se SHA-2 nebo SHA-3.
  • Hash není šifrování ani kódování. Slouží k ověření integrity.
  • HMAC přidává tajný klíč, takže správný otisk spočítá jen ten, kdo ho zná.
  • Elektronický podpis podepisuje hash dokumentu soukromým klíčem a ověřuje se veřejným. Certifikát říká, komu klíč patří.
  • Řetězení hashů drží pohromadě Git a blockchain: změna minulosti rozbije všechno za ní.
