Osolit heslo

Dva uživatelé, stejné heslo

Sůl je náhodný text, který se přidá k heslu před hashováním. Každý účet má svou. Zkus změnit heslo nebo vygenerovat novou sůl.

UživatelSůlUložený hash

Bez soli mají oba stejný hash, útočník ho vidí a zkouší proti oběma najednou. Se solí je každý hash jiný a luští se zvlášť. Sůl není tajná, ukládá se vedle hashe. Pro ukázku je tu rychlý hash SHA-256, skutečné systémy používají pomalé funkce.

Chyba v aplikaci

Data se nesmí splést s příkazem

Nejstarší trik s databázemi: aplikace slepí text od uživatele s příkazem pro databázi. Pak může uživatelův text změnit smysl příkazu.

Špatně: vstup se slepí s příkazem
jmeno = input("Jméno: ")
dotaz = f"SELECT * FROM uzivatele WHERE jmeno = '{jmeno}'"
cur.execute(dotaz)
Správně: vstup je vždy jen hodnota
jmeno = input("Jméno: ")
cur.execute("SELECT * FROM uzivatele WHERE jmeno = ?", (jmeno,))

Přirovnání: číšník s lístkem

Host napíše na lístek jméno. Špatný číšník přečte celý lístek jako příkazy, takže ho host přesvědčí i o dalších věcech. Parametrizovaný dotaz je lístek s kolonkou „jméno“: cokoli tam host napíše, zůstane jménem.

Vzdálené spuštění kódu (RCE)

Nejhorší možná chyba: cizí kód běží u tebe

RCE (Remote Code Execution) znamená, že útočník dokáže vzdáleně spustit vlastní kód na cizím serveru. Společný princip: program splete data s příkazem.

Čerstvý příklad · PHP, 21. 10. 2026

Takhle to vypadá, když se to děje právě teď

Co je veřejně známo

Tým PHP vydal aktualizace, které opravují dvě kritické chyby (hodnocení 9,2 z 10). Mohly by umožnit převzetí serverů dostupných z internetu. PHP běží zhruba na 70 % webů, včetně WordPressu.

Doporučení: aktualizovat hned. Dočasná nastavení riziko jen snižují, plnou opravu přinese až aktualizace.

Co si z toho vzít

Technické podrobnosti záměrně neuvádíme. Pro pochopení lekce nejsou potřeba. Podstatné je, že od zveřejnění opravy běží závod mezi správci, kteří záplatují, a útočníky, kteří hledají neopravené servery. Kdo neaktualizuje, je cíl.

Stav podle zpravodajství k 24. 10. 2026. Čísla opravených verzí najdeš na php.net a před hodinou si ověř aktuální informace.

Zkus doma

Hash hesla na tvém počítači

Spusť v Pythonu na svém počítači. Všimni si, že první hash je při každém spuštění stejný, druhý pokaždé jiný.

import hashlib
import os

heslo = "heslo123"

# 1) Bez soli: stejné heslo dá vždy stejný hash
print(hashlib.sha256(heslo.encode()).hexdigest())

# 2) Se solí a pomalou funkcí: pokaždé jiný hash
sul = os.urandom(16)
print(hashlib.pbkdf2_hmac("sha256", heslo.encode(), sul, 600_000).hex())

První hash (ten bez soli)

b4240791ce0be7b92ddd5091ae67234e5dff778e786dc0a3cb9846af0cf8b653

Zkus změnit jediné písmeno v hesle a sleduj, jak se změní celý hash. Z hashe se heslo přímo přečíst nedá, dá se jen zkoušet.

Shrnutí

Co si odneseš

  • Data unikají pěti cestami: člověk, slabé heslo, chyba v aplikaci, neopravený software, špatné nastavení.
  • Hesla se mají ukládat jako pomalý hash se solí. Prostý text a hash bez soli jsou chyba.
  • Znovupoužité heslo znamená, že jeden únik otevře víc účtů.
  • RCE je nejhorší chyba: cizí kód běží u tebe. Za většinou případů stojí splétání dat s příkazem a neaplikovaná záplata.
  • DDoS nekrade data, vyřazuje službu. Obrana: kapacita, filtrování a nenechat vlastní zařízení s výchozím heslem.
  • Obrana je ve vrstvách: záplaty, unikátní hesla, 2FA, minimální oprávnění, zálohy.
